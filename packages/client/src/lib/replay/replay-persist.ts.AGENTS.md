# replay-persist.ts — index

Debounced replay-cache writer. createReplayPersister(cache,debounceMs). Owns per-session raw-event buffer (monotonic by seq, dedup append). record(id,events,origin)/seed/drop/flush. origin: "live"|"replay". drop clears buffer + deletes cache entry. PROVENANCE: per-session `descended` set; seed() + replay-origin record() set it, live-origin record() never does. flush() persists only when descended, else returns SILENTLY and never deletes (store shared across tabs, buffers per-tab). Live-origin seq > max+1 = dropped frame → clears descended until re-seed; replay-path gaps exempt (compaction). CONTAMINATION: `contaminated` set marks buffers holding unvouchable live rows (live append while non-descended, or a live-gap hole). replay-origin record() CANNOT clear it — record dedups by seq, so replayed rows <= buffered max are discarded and would re-authorize the same poison. Only seed() (wholesale replace) clears it. See change: reduce-session-replay-traffic, fix-replay-cache-partial-payload-cursor.
`createReplayPersister(cache, debounceMs, getServerKey)` — third arg read at FLUSH time, not construction, so a buffer flushed after a server switch is attributed to the server now connected; `flush()` passes it to `cache.put`. New `resetBuffers()` drops ALL in-memory buffers/timers/provenance on server switch — NOT an invalidation: durable store untouched, since entries are server-scoped and the old server's stay valid for a switch back. Clears timers FIRST — a surviving debounce would re-persist a discarded buffer under the NEW key. See change: purge-replay-cache-on-reset-paths.
C3 lifetime bound: 4th arg `retainLimitOverride` (tests); production `retainLimit = max(DEFAULT_MEMORY_LIMITS.maxReplayEvents, MIN_REPLAY_WINDOW)` = the server full-stream window. `flush()` persists only the tail (`buf.slice(-retainLimit)`) while `maxSeq` stays the FULL buffer's max (cursor monotonic past trim); post-await the SAME buffer instance is re-sliced — an append during the in-flight write survives (reusing the captured payload would drop it, making the next live frame read as a dropped-frame gap → permanent provenance void). `schedule()` early-returns for non-descended buffers (their debounce is pure waste; every provenance-setting edge calls schedule() after the flag is set). See change: fix-archive-feedback-and-sidebar-perf (C3).

# bridge.ts — index

Main bridge extension entry (default export). Connects to dashboard server, forwards pi events via `mapEventToProtocol`, relays `ServerToExtensionMessage` commands back. Wires `PromptBus`, `DashboardDefaultAdapter`, provider register, role manager, flow listeners, metrics monitor, model/git/session trackers. `tool_execution_end` runs `inlineToolResultImages`; applies its result on result-identity change (not `inlinedCount>0`) so strip-only rewrites propagate. See change: fix-duplicate-inlined-screenshot. On `agent_end`, classifies terminal assistant msg via `classifyTurnActionability` + `EmptyActionableGuard.observe`: `continue` → `enqueueSystemFollowup(CONTINUATION_NUDGE)` (only when `bridgeFollowUp` empty); `surface` → forwards `empty_actionable_surface` event (non-error). Never leaves an empty-actionable turn silent-idle. See change: fix-gemini-subagent-silent-tool-schema-failure. Routes `role_remove` (emit `roles:remove`; on success re-emit `roles_list`); all `roles_list` sends carry `builtinRoleNames`. See change: add-custom-roles-ui. See changes: simplify-error-retry-single-card, fix-retry-error-lifecycle — no billing special-casing. Retry synthesis: `message_end` records error or closes active chain on first non-error/non-aborted assistant completion; `agent_end` emits waiting; armed `agent_start` emits deferred in-flight start only while tracker remains active; native `agent_settled` closes unresolved chain. Abort installs tracker cancellation before `ctx.abort`; only observed user `message_start` releases it. The floor-pi `agent_settled` synthesis path was RETIRED at the 0.85.1 floor (`agent-settled.ts` deleted): the bridge now consumes pi's native settle unconditionally, so there is no per-attempt compatibility settle and no expected-attempt deadline timer. See change: update-pi-core-0-85-adopt-apis. EventBus forwarding is per-channel `pi.events.on` subscription via `registerEventBusForwarding` (NOT an `emit` intercept -- `pi.events` is per-extension, so a patch never saw foreign emits; see change: fix-automation-run-lifecycle). Its handler treats subagent channels as reconcilable: forward live only when `sessionReady && isActive() && connection.isConnected`, else `subagentFrameBuffer.buffer` (covers `!sessionReady` AND transient WS drops — `sessionReady` stays true across reconnects, so gating on `connection.isConnected` keeps reconnect-window frames in the per-agent buffer instead of the shared FIFO ring). `flushPendingSubagentFrames()` after `sessionReady=true` AND in `onReconnect`; `subagentFrameBuffer.reset()` on session change/shutdown. `onMessage` handles `subagent_resync_request` → replies synthetic `subagents:started` `event_forward` from `subagentFrameBuffer.resync`. See change: fix-subagent-live-detail-reliability. Subscribes `agent_settled` (enriched): forwards the single native terminal settle; the per-attempt compatibility settle and its reconciliation timer were retired with `agent-settled.ts`. Registers `session_info_changed` → `autoNamer.onObservedName` (push external renames early; poll fallback) and `project_trust` → `decideProjectTrust` (auto-trust dashboard-spawned headless in `activationCwd`, captured at activation). See change: adopt-pi-074-080-features.
 `ctx.ui.notify` is no longer proxied onto `prompt_request`: the patch now installs `createNotifyProxy` (notify-proxy.ts), which sends `{type:"notify", sessionId, notifyId, message, level?}` on the dedicated channel — never PromptBus, no `as any` at the send site. See change: split-notify-from-prompt-request. Also wires inbound-drop diagnostics and transcript guards.

`initBridge()` maintains process-global ownership and accepts a one-shot owner-bound handoff for Pi `/reload`, `/resume`, `/new`, and `/fork` replacement instances. `session_shutdown` preserves reason-sensitive unregister behavior: `quit` sends `reason:"quit"`, replacement reasons defer unregister to session-change handling, and unknown legacy reasons send a terminal unregister.

Migration wiring (fix-bridge-mdns-migration-hijack): the autoStart-discovery `.then` no longer blanket-refuses via `decideRetarget(identityVerified:false)` — that also blocked every LEGITIMATE migration. Pinned endpoints still refuse (decideRetarget + `retarget_refused` record). Unpinned: the candidate goes through `connection.retargetTo(candidateUrl, {trigger, verify})` with `verify = probeEndpointReachability(http://<host>:<httpPort>/api/health)` on the record's HTTP port; adoption, refusal and fallback are decided (and recorded) on the connection. `ConnectionManager.onMigrationEvent` is the single record chokepoint → console.log + `transportDiagnostics` (`retarget_accepted`/`retarget_refused`, protocol union extended) — a re-target cannot occur without a record. `connection.noteRegistered()` called at the initial `session_register` send and inside `sendStateSync()` (the register-acknowledged marker driving reversal).


Event subscription: `enrichedEventTypes` (special handling) + `passThroughEventTypes` (forwarded verbatim). pi 0.84 additions to the pass-through list: `session_compact_failed` (>= 0.84.3, lets the server clear its `compacting` latch on the failure path), `ui_prompt_start` + `ui_prompt_end` (>= 0.84.4, bracket a BLOCKING `ctx.ui` prompt so the dashboard can tell agent-working from parked-on-a-user-prompt). Subscribing below the floor is inert -- older pi never emits them, so no version gate. Server-side derivation lives in `server/src/session/event-status-extraction.ts`.

`formatWatchdogFire(w)` renders a `watchdog_force_close` diagnostic, recorded via `transportDiagnostics` (durable in `server.log`; `console.log` alone dies under default `keeperLog.capturePiOutput:false`). Wired at BOTH `ConnectionManager` sites — primary and the `/dashboard-connect` move target, which `connection` is rebound to. Discriminator is `silentForMs`: at threshold = server silent; far above = timer ran late vs pending reads.
NOTE the heartbeat timer's `if (!isActive()) return` arm is UNREACHABLE: `initBridge` sweeps `prev.timers` with `clearInterval` BEFORE bumping `generation`, so the timer dies before its incarnation goes stale. Do not instrument it — a counter there can only report 0. See change: add-watchdog-force-close-diagnostic.
Reconnect heal is now SYMMETRIC: the existing mid-turn synthetic `agent_start` (`onReconnect`) is untouched, and the idle half sends one `session_heartbeat{agentRunning:false}` from the new `onPostFlush` hook. Spelled as a heartbeat, never a synthetic `agent_end` — that event carries run-boundary side effects (unread stamping, card reordering, OpenSpec clearing) a correction must not fire. The periodic heartbeat (`HEARTBEAT_INTERVAL` 15s) also carries `agentRunning: getBridgeState().isAgentStreaming`, which heals a drop on a socket that never closes. See change: fix-stuck-streaming-status-latch.

Subagent fan-out admission: registers a blocking `tool_call` handler AFTER the pass-through forwarder (first `{block:true}` wins — D8) returning `{block:true, reason}` for over-cap `Agent` calls, plus a `tool_execution_end` permit release. Gate + sampler live in `subagent-fanout-admission.ts` / `subagent-saturation.ts`; refusals are written via `pi.appendEntry("subagent-admission-refused", …)` and the counters are spread onto the heartbeat metrics. Never sets `terminate`. See change: bound-subagent-fanout-under-host-pressure.

`message_update` text snapshots use `MessageUpdateCoalescer` with a single-slot 50 ms window. Thinking/toolcall/unknown updates and lifecycle/EventBus boundaries flush first; generation plus stable message keys drop stale updates. Reconnect defers parked-update flush to a microtask so `ConnectionManager` drains buffered `message_start` frames first. Session switch, shutdown, and reload cleanup flush or clear the coalescer as appropriate. See changes: coalesce-message-update-text-snapshots, preserve-message-update-ordering.

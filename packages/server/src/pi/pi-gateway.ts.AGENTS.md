# pi-gateway.ts — index

WebSocket server for bridge extension connections. Routes `ExtensionToServerMessage` → `SessionManager`; pings every `WS_PING_INTERVAL` (60s), heartbeat timeout `HEARTBEAT_TIMEOUT` (180s). Exports `createPiGateway`, `PiGateway` (`start`/`stop`/`address`/`sendToSession`/`broadcast`/`findSessionByCwd`/`findSessionsByCwd`), `PiGatewayOptions`, `onSessionRegistered` callback (consumes pending spawn-attach intent). `findSessionsByCwd(cwd)` = plural prefix-match for folder-scoped reload (change: folder-resource-activation-toggle). See change: add-folder-task-checker-and-spawn-attach. Session owner guard maps sessionId → `{ws,generation}`; stale register/messages/unregister/close/heartbeat timers cannot mutate, delete, or unregister the current owner. `ws.on("close")` for current-owner `kind="automation"` sessions unregisters immediately (no reconnect grace) — headless one-shot runs never reconnect; every other session keeps the grace window. `closeSession()` only closes the owner socket; close handler owns lifecycle callbacks. See changes: finalize-automation-run-on-session-death, reload-resume-lifecycle.
Enforces **one live bridge per session id**: the claim point is the first-message identity block (NOT the `session_register` dispatch), and the contention decision runs above every register side effect (watchdog clear, placeholder cleanup, `resetHeartbeat`, callbacks, `onEvent`). Contention resolved by a bounded two-factor probe (`CONTENTION_PROBE_WINDOW` 5s, override via `PiGatewayOptions.contentionProbeWindow`): pong → incumbent keeps; no pong but `_socket.writable` → busy, incumbent keeps; neither → terminate incumbent, accept newcomer. Same-pid reconnect and placeholder (`source:"unknown"`) incumbents skip the probe. Loser gets `register_rejected` before the close. Messages from a socket that does not own the id are dropped; displaced same-pid sockets also fail a pre-register ownership gate and cannot reclaim the session. Accepted claims use one gateway-lifetime monotonic generation counter, so a stale socket can never match a reused generation after unregister/re-register. Per-socket message queue preserves order across the async decision. `ws.on("close")` cleanup and contention clearing both require current ownership; `stop()` terminates `wss.clients` (not `connections.values()`). Adds `contention` tracker + `findLiveSessionBySessionFile` (D5 resume guard). See changes: fix-duplicate-bridge-registration, preserve-dashboard-bridge-across-session-replacement.
